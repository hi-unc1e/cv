## 0x00 一般思路
正如我在文章《[记一次Java Servlet实战审计 - 先知社区](https://xz.aliyun.com/t/9153)》中说的那样，获取系统的源代码主要可以从几个角度来考虑：

1. **同类站扫目录。**
    1. 上Fofa搜索[同类系统](https://fofa.so/result?qbase64=TGlxdWlkIEZpbGVz)
    2. 导出资产列表
    3. 目录扫描。具体操作起来，就是使用`dirbuster`的字典`directory-list-2.3-medium.txt`来扫，工具就随便用个顺手的，`dirseach`（ps：它的字典`dicc.txt`也好用）

<u>结论：因为本身这玩意儿的发布形式都是镜像，统一部署的，当然不会有备份文件了。。。无果。</u>



2. **网盘泄露。**这套系统并不开源，一般国内的厂家发版的时候为图方便，都会放了一些在网盘，简单一搜就知道有无结果。

<u>结论：人家厂家本身有官网，没必要传网盘，麻烦。无果</u>





3. **Github、gitlab泄露**。搜了下——您看看，这像源码么？

![](https://cdn.nlark.com/yuque/0/2021/png/166008/1630070438027-9b845e42-dddb-4a98-a90a-4b1bc993f746.png)

<u>结论：无果。。。</u>



也不绕弯子了，但凡看过官网就知道：这公司很耿直，直接提供了试用......

这也正是本文主要想介绍的技巧：**利用厂家的安装镜像，获取源代码。**

## 0x03 单用户模式
下面的内容参考自[http://c.biancheng.net/view/1041.html](http://c.biancheng.net/view/1041.html)

> + 很多新手当面对“忘记 root 账户密码导致无法登陆系统”这个问题时，直接选择重新系统。其实大可不必，我只需要进入 emergency mode（单用户模式）更新 root 账户的密码即可。
> + Linux 的单用户模式有些类似 Windows 的安全模式，只启动最少的程序用于系统修复。在单用户模式（运行级别为 1）中，Linux 引导进入根 Shell，网络被禁用，只有少数进程运行。
>

**如何进入单用户模式**

现在，我们假设系统出现了问题，已经不能正常登录了。那么，如何进入单用户模式呢？首先需要重启服务器，在 GRUB 读秒界面按任意键，进入 GRUB 菜单界面，如图所示

![](https://cdn.nlark.com/yuque/0/2021/png/166008/1630068368807-111bdb82-a3a6-4dec-8255-ff58d9bd7dc0.png)

在想要进入单用户模式的 Linux 菜单上按"e"键，就会进入 GRUB 编辑界面，如下图所示：

![](https://cdn.nlark.com/yuque/0/2021/png/166008/1630068393585-5650a7e9-d60f-4b57-b2da-ca8331567d39.png)

找到`linux   /boot/vmlinuz-*`那行，江湖上传闻有两种常见的操作方式：

1. 【我常用】在最后添加`init=/bin/bash`，然后按 `ctrl+x`或者 `F10` 继续grub引导，此后的用户，即为root用户，可以在其中随意更改root用户的账号密码
2. （没试过）将它的ro recovery nomodestset及之后的东西替换为`rw single init=/bin/bash`，然后按 ctrl+x或者F10 进入单用户模式

![](https://cdn.nlark.com/yuque/0/2021/png/166008/1630068774970-0248e58f-8b69-4ade-a890-a7a4563db5b6.png)

总之，虽然单用户模式下面没有网络，但可以修改用户的密码呀~

在View层发现了风险点，当然要跟一下它之前的`Controller`，也就是`app\v3.5.12\app\controllers\admin\actionscripts_controller.rb`

函数列表如下

![](https://cdn.nlark.com/yuque/0/2021/png/166008/1630133303644-d7650983-b83a-455b-893c-b9e284ad5342.png)

其中，控制器的前两行是`before_action`，类似于Java Web中的Filter

![](https://cdn.nlark.com/yuque/0/2021/png/166008/1630135083921-27f8069a-fbb5-439e-9fe7-2ac192adf8ca.png)

使用`sanitize_filename`方法，对文件名参数进行了处理

```ruby
def sanitize_filename
    unless (@sanitized_filename = script_params[:script_name].gsub(/[^a-zA-Z0-9\-\_\.]/, "_").gsub(/^\./, "_").strip).present?
      render_error "Invalid Filename", {
        location: admin_actionscripts_url
      }
    end
  end
```

校验了逻辑只允许`a-zA-Z0-9-_`，其它的字符都会被替换成`_`。

总之，这个功能点，先在Controller层就校验了文件名，后面在View层调用的也是`shellescape`转义过的安全执行函数——这个过滤还挺够劲儿。
